# codeloom 的界面判据

这边管**用户看得见的东西**：它长在哪、什么时候出现、失败之后留下什么。
给模型看的字见 `codeloom-prompt-standard`，代码注释见 `codeloom-comment-standard`。

## 范围

适用：`frontend/src` 里任何会改变用户所见、所读、所能操作的东西 —— 布局与间距、反馈落在哪一栏、
浮层的开关与位置、加载与空状态，以及**用户看得见的文案**。

不适用：用户看不出来的纯重构。

## 令牌优先

- 颜色、圆角、间距**先用现有的令牌**，不写字面值。要动之前先看"最像的那一栏"用的是什么，跟着它。
- 整块的观感也一样（卡片、分隔、那几档灰、空状态）：有现成的就用现成的，别另起一套。
- 强调靠**颜色深浅和字号**，别靠字重堆。

## 复用优先

- 能**扩**已有的组件或交互（加一个 prop、加一个菜单项），就别在旁边并一个平行的。
- 图标用现有集合里语义最近的那个。
- 只有图标、意思又不显然的动作，得让人看得出来它是什么。

## 反馈分档

按"这条消息活多久"选那一档：

| 情况 | 落在哪 |
|---|---|
| 刚发出去、还没进流 | **灰显回声**，一进流就换成真的 |
| 操作失败 | **就地 notice**（`tone: 'bad'`），而且**数据留着** —— 失败不清内容 |
| 那一栏本来就是空的 | **空状态**居中，别把错误挂在空白上 |
| 按下去到生效之间有几秒 | **状态行**（「正在停…」「正在读取…」），而且它必须是**那条路上唯一的反馈** |
| 正在加载 | **脉动占位**；一屏只用一种加载观感 |

- 反馈落在**用户正看的那一栏**里、跟着它一起走；**不做全局浮出**（那一栏收起来时，浮出的那条也该跟着收）。
- **只报结果**，不报"还在处理"；上面那条状态行是唯一的例外，条件是"中间那几秒没有别的反馈路径"。
- **通知不得改变布局**：预留它的位置，或者叠上去 —— 不许把相邻的东西挤走。
- 没有上下文就别写"加载中"这类字。

## 浮层与菜单：每一样都要过三关

- **可关闭**：点外部关掉；能收焦点的还要 **Esc** 关掉。
- **贴边会翻面**：靠窗口边缘时翻到放得下的一侧；两侧都放不下时**别来回跳**。
- **不被裁掉**：能逃出 `overflow` 祖先，也不被相邻元素盖住。

滚动条全站一套（`index.css` 里那一条），别给单个组件另写；核对它既没溢出容器、也没被圆角切掉。

## 文案

- **一句话说清**；中文通知至多两句时**不点句号**。
- 不要内部行话和类型名，除非那串报错是排障必需的。
- 状态行要短到能塞进它所在的那条缝里。

## 间距与对称

- 挨着的东西之间有**有意留的缝**，不要无意的紧贴。
- 平行元素用**同一个**间距和尺寸；一处没来由的不一样，通常说明漏了一个共用的值。
