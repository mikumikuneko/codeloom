# 决策：关于行为的断言，证据是跑过一遍

## 是什么问题

注释、报告、文档里那些"关于行为"的话 —— 命令怎么写、默认值是多少、报什么错、平台之间有什么差异 —— 凭什么算数？

## 定了什么

证据是**跑过一遍**：不是记忆、不是类比、不是"隔壁文件里是这么写的"。跑不了的（没有密钥、没有那个环境）就**明说跑不了**，不把它写成事实。

还有一条是从错里学到的：**探针要跑在目标那个环境里**。在自己习惯的 shell 里验应用那侧的环境，测出来的结论不算数。

## 还考虑过什么，为什么没选

- **照抄注释或文档**：实测里被推翻过好几次 —— 编码假设、默认值、SQL 保留字、"窗口是 64k"这些都翻过车，其中"窗口 64k"那条还直接导致了压缩时机是错的。
- **推导**（"按理说应该是这样"）：同样翻过车，而且推导错了的时候更难发现，因为它自带一套听起来合理的理由。
- **不确定就先写"大概"**：含糊的断言比没有断言更糟 —— 读的人会把它当事实用。

## 代价与换来的

- 慢：有时要搭一个临时探针（用完撤掉，别留在仓库里）。有些结论因此推迟到"有条件测的时候"才写下来。
- 这条后来升级成了仓库级的规矩（写在 `CLAUDE.md` 里），因为它是这一路返工的最大来源。
- 换来的是：写下的每一句关于行为的话都有出处；错了也错得清楚（是那次实测错了，不是"听说"）。
