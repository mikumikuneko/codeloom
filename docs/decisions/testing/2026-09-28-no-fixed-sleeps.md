# 决策：测异步不睡固定时长，等到条件成立

## 是什么问题

测"一轮跑完了""事件推到了"这类异步结果，怎么等？

## 定了什么

不睡固定时长。用"**等到某个条件成立、带超时**"的辅助（`Await`）：等的是"库里多了一条事件""状态变成等待用户"这种可观察的条件。

## 还考虑过什么，为什么没选

- **`Thread.sleep(300)`**：它是个猜出来的数 —— 快机器上白等，慢机器上不够。更要命的是**它会安静地通过**：睡不够长时测试照样是绿的，只是断言可能刚好没抓到东西（或者抓到一个中间态），于是"过了"这件事没有意义。
- **把超时调大一点**：只是把"猜错"的概率压低，性质没变。
- **轮询一个大循环直到超时**（其实就是上面那个辅助）—— 这是选的那个，区别在于等的是**明确的条件**而不是一个时间。

## 代价与换来的

- 每个等待都要写清"等到什么条件"，比一行 sleep 麻烦。
- 换来的是：测试的时钟由被测行为决定 —— 该快的时候是毫秒，慢的时候超时失败会**响亮地**报出来。
