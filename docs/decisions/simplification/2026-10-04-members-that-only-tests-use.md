# 决策：只给测试用的生产成员，一律移走

## 是什么问题

生产类里有一些方法/字段，扫一遍发现**只有测试在调用**（为了断言方便，或者为了让测试能构造出某个状态）。留着还是删掉？

## 定了什么

**一律移走**（删掉，或者改成测试自己构造）。执行时全仓扫了一遍，删了十八个成员和两个字段。

判据是用户给的、也是**可判定**的那一条：**数生产代码里的调用点**。不数就是 0 → 它不该在生产类里。

## 还考虑过什么，为什么没选

- **按"测试需要的是不是产品能力"逐个判断**（更宽的口子）：那要求做一次判断，而判断就会有不一致的边界；"数调用点"不需要判断，两个人分别数结果一样。
- **加 `@VisibleForTesting` 之类的注解留着**：注解只说明了它的用途，不改变"生产 API 上多了一个只为测试存在的口子"这个事实 —— 而那种口子会被下一个人当成正常 API 用。
- **改成包级可见**：仍然在生产类里，只是门缝小了点。

## 代价与换来的

- 有些测试要多写几行（自己造状态、或者走真实入口）。
- 换来的是：生产类的 API 等于"生产里真的在用的东西"，测试也顺带被逼着走**真实入口**（那本身就少一类"测试验的是测试自己造的状态"的假绿）。
