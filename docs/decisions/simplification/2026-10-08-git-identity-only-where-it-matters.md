# 决策：提交身份只出现在会产生提交的入口上

## 是什么问题

`GitClient` 的每个执行入口（`run` / `runOrThrow` / `runWhole`）都要求传一个提交身份，而真正需要它的只有会产生提交的那几条命令。写 `null` 的调用点有十几个 —— 而且没人报错，因为给一条读命令多带两个参数是无害的。

## 定了什么

入口拆成两族：`run` / `runOrThrow` **不带身份**（读命令，以及那些不写作者信息的写命令：`add`、`checkout`、`reset`、`clean`、`worktree`），`runAs` / `runAsOrThrow` **带身份**（只有 `commit` 和 `merge` 用它）。`runWhole` 那个从来没人给过值的形参直接删掉。

## 还考虑过什么，为什么没选

- **只删 `runWhole` 的那个死形参**（最小改动）：能让静态检查闭嘴，但代码整体仍在说"每条 git 命令都要带身份"，而事实是只有三条需要 —— 而且这个错误**没人会拦**（多带两个 `-c` 不会失败、不会被检查发现）。
- **保留现状、加一句注释说明"读命令传 null"**：注释治不了形状；下一个加命令的人照样会顺手传个身份进去。
- **给身份加一个"非空"约束、让 null 编不过**：那只是把 `null` 换成另一个占位值（比如 `CommitIdentity.none()`），形状没变。

## 代价与换来的

- 四个入口的拆分、调用点与测试跟着改（一次性的）。
- 换来的是：**"这次提交是谁写的"从代码上看得见** —— 身份只出现在两个方法里，看那两个方法就知道谁在写提交；而"给一条读命令多带一份身份"这种没人能发现的错误，从此没有地方可以发生。
