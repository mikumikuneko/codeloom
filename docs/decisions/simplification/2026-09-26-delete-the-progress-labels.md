# 决策：进度标签当天做完当天删

## 是什么问题

跑一轮的时候，"现在在干什么"能不能有个标签（"正在读文件""正在跑测试"）？做了，当天又删了。这条记的是**为什么该删**。

## 定了什么

不做进度标签（`ProgressReporter` / `ProgressLabel` 删掉）。界面上的"在做什么"由事件流本身给（工具调用、输出、状态行），不需要另造一层标签。

## 还考虑过什么，为什么没选

- **留着，将来前端要用**：它是**给观看者**的东西，而做的时候我们没有前端、没有观看者 —— 也就是说，它当时没有任何消费者。
- **对照着别人的源码里有这个机制，所以我们也做**：这是做它的**真实原因**，也是坏理由。做之前该问的是"**我们有没有这个问题**"，而不是"别人的源码里有没有这个机制"。按清单推进最容易犯的就是这个错。

## 代价与换来的

- 一点返工（做完就删）。
- 换来的是记下一条更值钱的规矩：判断一个机制该不该有，看的是**我们这边有没有对应的需求**，不是它在一个更复杂的系统里存不存在。之后遇到同类问题就快了 —— 比如读后写保护、呈现层那几处，都是先问"我们的形状是什么"再动手。
