# 决策：不做 token 账本，连它的字段一起删

## 是什么问题

要不要记一份 token 账本：哪一轮花了多少、花在谁身上、哪一部分算"平台替你花的"？

## 定了什么

不做。删掉 `TurnTokensUsed` 上的"来源"字段（`TokenSource`），以及围绕它的一套判定。每轮的用量照常记（那是看得见的部分），但不再试图区分"谁的钱"。

## 还考虑过什么，为什么没选

- **做一份，审计时能分清平台与用户**：它依赖的前提是"平台在替用户花钱"。这个项目是 BYOK —— 用户拿自己的 key 付款，**没有平台的钱**，"分清哪笔是平台的"这件事没有对象。前提不成立，字段就是没有真值的字段。
- **做一份用来拦额度**：那也不是用户要的。用户要的是**看得见**（用量摆在界面上），不是被拦住。
- **保留字段、只改注释让它"语义正确"**：字段本身是错误前提的产物，改注释治不了。

## 代价与换来的

- 动了持久化格式：旧行里多出来的键靠"读的时候忽略不认识的属性"处理（跑过测试，历史行仍可读）。
- 换来的是：事件流里少一类**没人读**的字段。一条没人读的字段比没有它更糟 —— 它会让后来的人以为"系统在这一层上有这个区分"。

## 什么情况下该重新考虑

如果将来有平台出钱的额度（比如免费试用、配额），那时"这笔算谁的"才有对象，账本才值得做。
