# 决策：加了 `delete_file` 工具又撤掉 —— 修那条路，不加一个工具

## 是什么问题

系统提示词里写着"验证完把临时文件收掉"，而 agent 唯一的删除办法是 `run_command` 跑 `rm` —— 那条路在这台机器上是死的：白名单里的 `rm`、`rmdir`、`mv`、`cp` 四个命令在 Windows 上全都跑不起来（不是被拒，是启动就失败）。于是很自然地想：给它加一个 `delete_file` 工具。

## 定了什么

加了，撤了。真正修的是**那条路**（命令走一层 shell 之后，`rm` 能用），不是加一个我们独有的工具。

## 还考虑过什么，为什么没选

- **保留 `delete_file`**：那是平台自己发明一条路，而模型的词汇里本来就有删除这件事（它会写 `rm`）。发明一个只在我们的平台上存在的工具，等于让它多学一套只有这里管用的说法。
- **只把白名单里的命令按平台改名**（比如换成 Windows 上存在的等价物）：那变成"删文件的第二条路"，两条路迟早不一致。
- **只把提示词里"验证完就收掉"删掉**：最诚实的一种（能力没有就别要求），但问题还在 —— agent 依然删不掉一个临时文件。

## 代价与换来的

- 撤净要动一圈：工具文件删掉、注册表恢复、测试与断言跟着收（加它的时候动了多少，撤的时候就得动多少）。
- 换来的是：模型的工具词汇回到**正常分辨率** —— 它用 `rm` 就能删文件，不需要知道我们这个平台特有的东西。
