# 决策：模型列表从服务商现拉，不做手填兜底

## 是什么问题

用户选了某个模型服务之后，模型清单从哪来？内置一份、让用户自己填、还是问服务商要？

## 定了什么

**从服务商的模型接口拉**（`/v1/models`），**不做手填兜底**；**拉取只在用户点开那一刻发生**（那是一次带用户密钥的真实外部请求）；拉不到就**返回 502 并说清是哪种失败**，不返回空列表。

## 还考虑过什么，为什么没选

- **内置一份模型清单**：它会在某天悄悄过期，而症状是"用户选了一个已经下线的模型"。
- **让用户手填模型名**：那是把"知道有哪些模型"这件事推给用户，而它本来可以问。
- **在后台定期刷新清单**：那会变成"拿着用户的密钥在我们不知道的时候反复打人家的接口" —— 而且拉清单必须带那把密钥（那是密钥被解开的第二个地方，边界是**只发给这把密钥自己的归属方**）。
- **拉不到就返回空列表**：用户看到"这个服务商一个模型都没有"，而真实原因是网络或者密钥不对。

## 代价与换来的

- 点开下拉时会有一次真实的外部请求（几百毫秒到几秒），拿不到就明确报错。
- 换来的是：模型清单永远和那家服务商对齐；而且"密钥被用在哪"这件事只有两处（发对话、拉清单），两处都只发给它自己的归属方。
