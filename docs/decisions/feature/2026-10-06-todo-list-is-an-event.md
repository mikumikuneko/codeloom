# 决策：待办清单落成事件，每轮把整份重新注入尾部

## 是什么问题

模型给自己记的待办清单（"先做 A 再做 B"）存哪？存内存里跟着那一轮走，还是落成事实？

## 定了什么

**落成事件**（`TodoListUpdated`，每次是**全量替换**、带三态）；投影把它**每轮无条件注入到上下文尾部**；回滚时它跟着一起退。

## 还考虑过什么，为什么没选

- **只存内存**：省事，但会连着丢四件事 —— 压缩之后清单没了、回滚之后清单对不上、"断线重连"看到的和模型看到的不一致、**队友看不到对方的计划**（而"看得见对方在做什么"是这个产品的核心）。
- **增量 diff**（只记变化的那几项）：模型写整份比算 diff 可靠，而且整份替换**天然幂等、重试安全** —— 一条事件丢了再补一次也没关系。
- **条件性提醒**（"你最近没用过待办工具，提醒一下"那类做法）：那是**催**，抄过来正好和我们的目的相反（我们要的不是催它用，而是让它写的清单一直可见）。
- **只在头部注入一次**：压缩会把头部吃掉，清单就消失了；放尾部每轮重申，压缩之后它还在。

## 代价与换来的

- 每轮多一条消息（放在**末尾**，所以不破坏 prompt 前缀缓存）。
- 换来的是：清单是事实（回滚、压缩、重连、观战四条路都对得上），而且是模型自己维护的、队友也看得见的计划。
