# 决策：平台写给模型的原文，一个字都不上界面

## 是什么问题

有些"事件"的正文其实是**平台写给模型的指令**（比如"上一步的输出被截断了，别道歉，接着做"）。这些文字进了事件流，界面上要不要显示？

## 定了什么

**不显示原文**，换成一句人话；**认不出来就什么都不显示**（宁可少说一句）。判断依据是**结构化的原因字段**（`reason`），不是匹配正文。

还有一个相关的取舍：那条提示里如果要求模型"接着做"，界面上要显示的是一个"人话版"的说法（"已经打断 · 接下来要它做什么？"这种），而不是命令原文。

## 还考虑过什么，为什么没选

- **原样显示**：那不是"一句提示"，是**提示词** —— 里面有对模型的命令（"不要道歉、不要复述"），端到用户面前读起来像界面在训人。
- **按正文去识别**：那串字随时会改，改一次这个判断就断；所以按 `reason` 这类结构化字段认。
- **认不出来时显示原文**：那会在每次新增一种提示时泄露一次；宁可不显示。
- **把提示词从事件流里去掉**（只留给模型）：它必须落库（模型可见的都要能从日志重建），所以"不显示"是在**界面这一层**做的决定。

## 代价与换来的

- 界面上偶尔会有一处空白（认不出的原因），而不是一句话 —— 这是主动选的。
- 换来的是：提示词不会以界面的口吻出现在用户面前；而"提示词是写给模型的"这条边界在代码里有一个明确的位置。
