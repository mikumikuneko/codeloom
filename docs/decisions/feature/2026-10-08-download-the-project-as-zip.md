# 决策：下载这个项目 = 主干那一刻的 zip

## 是什么问题

用户要把项目拿走（备份、离线看、发给别人）。界面给不给一个"下载"？给的话，下的到底是哪一份？

## 定了什么

文件树头部一个下载图标 → `GET /api/projects/{id}/archive`。服务端用 `git archive` 导**主干**，而且**只导项目根那棵子树**（`main:untitled`，所以 zip 里不会多出 `untitled/` 这一层）。导出先落到一个临时文件，再流给浏览器，**发完就删**。只有成员能下 —— 不是成员回 **404**（连"这个项目在不在"都不告诉他）。

前端就是一个图标 + 顶层导航：响应带 `Content-Disposition: attachment`，页面不会跳走；cookie 会被自动带上（这正是会话 cookie 比"头里带 token"省事的地方 —— 否则得先取回 blob 再存盘）。

## 还考虑过什么，为什么没选

- **导"我正在看的那棵树"**（甚至让它跟着工具栏那个"我的/主干"开关走）：各人树上是半成品，而"下载哪个"要多问一句；主干才是"这个项目现在是什么样"。按钮的 label 里就写着主干 —— 语义只有一个。
- **自己遍历文件打包**：那等于把"这个提交里到底有什么"重新实现一遍 —— 忽略规则、`.gitattributes` 里的 `export-ignore`、子目录结构都算在内，而这正是 git 已经做对的事。
- **把 zip 收进内存再发**：子进程读取那条路会按字符集解码，二进制过一趟字符集就是坏数据。所以让 git 自己写文件（`--output`），stdout 保持空。
- **临时文件不删**（等系统清理）：那是把自己建的东西留给别人收拾；`StreamingResponseBody` 的 `finally` 里删，成功和失败两条路都走到。
- **不写测试**：这条路上有两件会**悄悄**坏掉的事 —— 导的是哪个提交、谁能下 —— 而"点一下下载"看起来太简单，简单到不会有人替它们担心。

## 代价与换来的

- 每次下载跑一次 git + 落一个临时文件（大仓库时这份开销在磁盘 IO 上）。临时目录用系统临时目录 + 随机名。
- 导的是**主干那一刻**的内容：不含任何人的未提交改动，也不含 agent 正在写的东西。这是要的。
- 文件名会带上项目名（中文会走 RFC 5987 那种编码形式），项目名里不能进文件名的字符统一换成连字符。
- 换来的是："下载"这件事有确定的语义，而且它借的是 git 自己的导出语义 —— 换个说法，**它导的是一棵能被 git 认出来的树**，不是磁盘上一堆文件的快照。

## 什么情况下该重新考虑

如果以后要"导某一条会话（或某个 checkpoint）的版本"，那只是 treeish 换一个值 —— 这条路的形状不用动。
