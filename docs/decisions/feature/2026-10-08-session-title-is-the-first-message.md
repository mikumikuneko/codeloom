# 决策：会话列表那一行的标题，用用户开口的第一句

## 是什么问题

会话历史列表里，每一行拿什么当标题？原来是"说话人"（也就是显示名）—— 而那一栏列的全是**同一个人**的会话。

## 定了什么

**用户说的第一句话**（只往前扫 50 条事件、超过 80 字截断加省略号）；还没人说过话就显示"还没有说话"。

## 还考虑过什么，为什么没选

- **说话人**（原状）：同一栏里全是同一个人的会话，显示"root / root / root"等于没区分。
- **轮次 + 时间**：能排序，但认不出是哪一条 —— 人记得住的是"我开头说了什么"。
- **让模型生成一个标题**：多一次模型调用，而且标题会在你回头找的时候和你记忆里的那句话不一样。

## 代价与换来的

- 列表接口要多读一点事件（扫前 50 条就够 —— 那句话必然在头几条里）；截断到 80 字是"列表那一行装不下更长的"。
- 换来的是：**一眼认出是哪条会话**，而且这个标题是用户自己的话，不是我们编的。
