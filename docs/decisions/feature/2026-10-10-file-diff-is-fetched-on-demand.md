# 决策：某一轮里某个文件改了什么，按需去问 git，不写进事件流

## 是什么问题

"这一轮改了什么"那条事件里只有**文件名和增删行数**，看不到正文 —— 于是界面上点开一个文件，看到的是它**现在**的样子，而不是"它刚才变了什么"。

`edit_file` 那一类还有点救：界面上拿它的工具参数自己算一份行级 diff。但**命令改的文件**（格式化器、代码生成、`sed -i`）连这一点都没有，而"命令也会改文件"正是那条事件存在的理由之一。

## 定了什么

给项目加一个成员可见的端点：

```
GET /api/projects/{projectId}/diff?commitSha=<sha>&path=<项目相对路径>
→ { text, truncated }
```

后端跑 `git diff <sha>^ <sha> -- <gitPath>`，正文有字符上限，**超了就截断并如实标记**，不报错 —— 一份被截断的 diff 仍然有用，而"打不开"没有任何用。

**指针本来就在事件里**：`WorkspaceChanges.commitSha` 的注释写着「事后要复核"当时到底改了什么"时，从它入手」。所以这件事不需要新记任何东西，缺的只是"拿着它去要一次"。

区间和"改了哪些文件"那条用的是同一个（`<sha>^ <sha>`）。`numstatOf` 用的是简写 `<sha>^!`，**实测**过：普通提交上两者结果完全相同，差别只在根提交上（`^!` 会悄悄退化成"那个提交 vs 当前工作树"，而 `sha^` 会明确报错）。取同一个区间，是为了让"这里说改了 3 行、点开却有 40 行"这种不一致不可能发生。

## 还考虑过什么，为什么没选

- **把正文写进事件**：事件表是**每一处读取都要过一遍**的东西（断线补齐、回放、崩溃恢复），而这条事件每轮都追加。一次格式化能让一轮的正文到 MB 级，等于让每一个读事件的地方都为它买单 —— 而正文只有人**点开某一个文件**时才需要。
- **不出端点，硬让界面上自己算**：界面上只有 `edit_file` 的参数，命令改的那些文件它根本不知道有改动。
- **照抄"文件数 / 总大小"那几条上限**：那是"一次把所有文件都算出来"才需要的；我们是**按一个文件取**，只有"单文件太大"这一条有意义。
- **算不动就退回"整文件替换 + 一个'这是粗的'标记"**：那是"自己在内存里算行 diff、可能算太久"才需要的降级。我们把行 diff 交给 git，它不会"算太久"，只会被我们的超时掐掉 —— 那种情况该**如实报失败**，不该编一份粗的出来。

## 代价与换来的

- 代价：多一个端点、每问一次起一个 git 进程。
- 代价：提交被回收之后，很旧的那些轮**问不出来**了。那时如实报 404，不编 —— 界面上要说清"这一段查不到了"，而不是显示一个空的 diff（空的 diff 和"没改过"长得一模一样）。
- 换来的是：**命令改的文件也有正文可看**。而"命令也会改文件"正是那条事件当初存在的理由之一 —— 在此之前，这一半的承诺是空的。

## 什么情况下该重新考虑

如果哪天要多一个"整轮评审"的视图（一屏把这一轮所有文件的正文字都摆出来），按需取会退化成"每轮一次 git + 一次串行等待"。那时该重新谈的是"存一份"（以及存哪、给谁看），而不是把这条路删掉。
