# 决策：对方新建了文件，平台自动给他的 agent 捎一句话

## 是什么问题

A 在自己的树里新建了一个文件（一块新功能）。B 的树里根本没有那个文件 —— 没有任何现成的机制能让 B 知道"你要做的东西 A 已经在做了"。这个信息差是**重复劳动**的主要来源。

## 定了什么

平台**自动**给对方的 agent 捎一句留言（走"留言"那条通道，进对方下一轮的上下文）：**只报新建**、**只提醒不拦**、**不经过人确认**、发给对方**轮次最多的那条会话**。

## 还考虑过什么，为什么没选

- **让模型自己判断要不要说**：这里有**客观信号**（新增/跟踪状态里的 `A`），不需要懂业务就能判定；交给模型只会变成"有时说有时不说"。
- **发之前让用户点一下确认**：那会变成一个总在弹的确认框（每一轮都可能触发），用户三下之后就开始闭眼点。
- **报所有改动**（改的也算）：改一个已有文件可能只是修个 typo，全报的话对方连收十轮就把它当背景噪声了。
- **只提醒、不拦**（这条是选了的取舍）：该不该重复做是**人**的判断 —— 平台的职责是把信息送到，不是替人决定。

## 代价与换来的

- 每一轮可能多一条给对方的留言（噪声与信号的取舍，靠"只报新建"控制）。
- 发送目标只能选"轮次最多的那条会话"（会话表里没有"最近活跃"这种列），所以偶尔会送到一条不是他正开着的那条 —— 留言会在下一轮被领走，不丢。
- 换来的是：**这一条补的是"信息差"，不是"防冲突"** —— 两个人可能仍然做重复的事，但至少不会因为互相不知道而重复。
