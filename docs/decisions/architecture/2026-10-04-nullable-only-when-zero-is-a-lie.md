# 决策：数值字段什么时候用包装类型 —— 看 0 算不算真话

## 是什么问题

事件里的数值字段（token 用量之类）用基本类型还是包装类型？这不只是风格：基本类型的默认值是 0，而 0 有时候是**一句假话**。

## 定了什么

判据一句话：**0 在这个字段上说得通吗？** 说得通用基本类型；说不通用包装类型，让"没有值"是 `null` 而不是 0。

按这条判过两次：上下文用了多少 token 的字段用包装类型（0 意味着"没测到"，那是假话）；思考用了多少 token 的字段用基本类型（0 是常态真值）。

## 还考虑过什么，为什么没选

- **一律用基本类型、拿 0 当暗号**：那会让"没读到"和"真的是 0"分不开 —— 而读的人（界面、压缩逻辑、审计）会各猜一套。
- **一律用包装类型**：每个读的地方都要处理空值，而大多数字段的 0 是真的。
- **为了兼容库里已有的行都用包装类型**：那些行马上就被清掉了，这不是理由。真正的理由是上面那条判据 —— **以后加字段不用记得"改字段要清库"**。

## 代价与换来的

- 同一种事件里会出现两种风格，需要这条判据来解释（所以它写成了判据，不是一条条特例）。
- 换来的是：每个字段的"空"都有明确含义，读的人不用猜。（这条判据也是"删字段之前先问谁会读它"那类问题的近亲。）
