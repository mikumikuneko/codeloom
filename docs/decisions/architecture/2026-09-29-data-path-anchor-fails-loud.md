# 决策：数据目录的落点由一处决定，找不到就报错

## 是什么问题

运行时数据（项目仓库、每人的工作区、git 的加固目录）放在哪？怎么找到那个位置？

## 定了什么

**落点由 `DataPaths` 一处决定**：从当前目录向上找 `.git`（没有就再往上），找到的位置就是"应用的工作根"，数据全放在它下面的 `data/` 里。**找不到就直接报错，不回退到别的位置。**

## 还考虑过什么，为什么没选

- **每条路径各写各的**（应用自己解析一次、工作区管理再解析一次、清理逻辑再解析一次）：那是原来踩过的坑 —— 同一次运行能在两个位置各建一份数据，而且两份都"看起来是对的"。
- **找不到锚点就退回当前目录或系统的临时目录**：那会把数据写到一个谁都没预期的地方（跑两次得到两份状态，重启后像"数据没了"）。**直接报错更便宜**：一次明确的失败，换来"位置永远是同一个"。
- **把它做成可配的绝对路径**：能配也保留；但默认行为要能自己找对，否则每换一次工作目录就得改配置。

## 代价与换来的

- 在一个没有 `.git` 的目录里直接跑会启动失败（这是有意的：与其猜，不如说清）。
- `.gitignore` 里那条忽略 `data/` 就是跟着这个约定写的（连历史位置的 `repos/`、`workspaces/` 也一起留着忽略 —— "该被忽略的东西没被忽略"是那种要到提交时才发现的事）。
- 为什么非要用"向上找锚点"这种办法：**纯配置做不到这件事** —— Spring 不把"配置文件所在的那一层"暴露成占位符，配置里能拿到的只有"用户主目录"和"当前工作目录"这两个，而这两个都不等于"项目在哪"。所以要么向上找锚点，要么把绝对路径写死（那 clone 到别处就崩）。
