# 决策：覆盖前比较读到的版本

## 是什么问题

2026-09-29 的[覆盖需要先读过](2026-09-29-overwrite-needs-a-prior-read.md)只要求“这一轮读过”，明确不比修改时间、也不比内容。当前实现不是这样：`ReadLedger` 记录读取时的修改时间和字节数，`write_file` / `edit_file` 在写之前用 `changedSince` 再比一次；文件在读后被改过会拒绝并要求重读，`ToolTest` 也钉住了这个行为。两种说法不能同时成立，需要以实际行为为准重新记录。

## 定了什么

- `ReadLedger` 为每个读过的文件保存版本：修改时间、字节数，以及是否读到整份。
- `read_file` 成功读取、`write_file` 写入、`edit_file` 修改成功后都记录当前版本；错误路径不记录。
- `write_file` 覆盖已存在的文件前要求有记录，且必须是整份读取，并且版本未变；否则失败并提示重读。
- `edit_file` 要求有记录，且版本未变；不要求整份读取，因为它只替换逐字匹配的局部内容。
- 从历史重建的账本没有版本，`modifiedAt` 为 null；这种记录按“版本未知、视为未改过”处理，否则重启后正常的整份覆盖会被拦下。
- 检查和写入之间仍有 TOCTOU 窗口，本决策不把它说成原子；真正的写入失败由写入步骤报告。

## 还考虑过什么，为什么没选

- **只记“读过没有”，不比版本**（2026-09-29 的选择）：在共享工作区里，读完到写之间对方可能刚改过；不比较就会用旧内容静默覆盖别人的修改，`edit_file` 甚至可能把旧位置上的匹配替换掉。
- **比完整内容/哈希**：读路径故意是懒的，大文件只读需要的部分；为了写前比较把整个文件物化出来，代价和收益不对等。
- **加租约或锁**：租约保护的是执行者，不保护“人手工改了文件”；把检查变成锁也挡不住读与写之间的时间差。

## 代价与换来的

- 代价：每次覆盖/修改多一次 `stat`；修改时间和大小都没变的内容变化仍发现不了；历史重建后版本未知，只能按未改过处理；TOCTOU 窗口仍在。
- 换来的是：常见的外部修改（另一个 agent、人手工保存）会在写入前被发现，模型得到“先重读”的明确指令，而不是静默覆盖。

## 什么情况下该重新考虑

如果以后写入路径能提供原子比较交换，或者读路径能廉价地保留内容哈希，可以把“版本未知按未改过”和大小/时间比较升级成更强的内容校验；那是一个新决定，不是把这一篇改回去。
