# 决策：退出只动成员关系，项目不做"墓碑"

## 是什么问题

一个人退出项目（或者干脆不想再看到它）时，那个项目算什么？标一个"已删"留在库里？还是让别人的东西跟着一起消失？

## 定了什么

**退出只动"谁在里面"**（`ProjectDeparture.leave`）：去掉成员关系、清掉这个人名下还没处理的留言请求；项目本身、另一个人的工作区、以及代码全都不动。

表结构上这是两件事，`owner_id` 和 `project_member` **回答的不是同一个问题**：`owner_id` 是"现在谁是房主"，成员表是"现在谁在里面"；有一条不变量 —— **房主必须在成员表里**。

## 还考虑过什么，为什么没选

- **墓碑删除**（给项目打一个"已删"的标记）：那会让"这个项目到底还在不在"在**每一处读路径**上都要记得判断，一处忘了就是幽灵项目；更要紧的是它允许一个人单方面让一个还有别人的项目消失 —— 而另一个人的代码和会话都还挂在上面。
- **退出就删掉他的工作区**：那不是"退出"该干的事 —— 退出是成员关系，不是销毁他的东西；他哪天回来还该看到自己的树。
- **把房主转移做成自动的**（谁最后走谁就是房主）：不变量好维护，但"谁是房主"这件事会变得不可预期；现在是有明确的转移动作。

## 代价与换来的

- 需要多维护一条不变量（房主在成员表里），转移房主要显式做。
- 换来的是：一个人的离开不会伤到另一个人；"这个项目还在不在"永远等于"还有没有成员"，不需要额外标记。
