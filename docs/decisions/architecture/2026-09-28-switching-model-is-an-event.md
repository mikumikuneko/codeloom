# 决策：换模型是事件，不是改配置

## 是什么问题

用户把这条会话换一家模型服务（换供应商、换模型）。这件事算"改了个设置"，还是"发生了一件事"？

## 定了什么

**落成事件**（`ModelChanged`），**下一轮生效**。当轮已经拿到配置快照了，中途改靶说不清"这一轮到底用的哪个模型"，所以换模型时要抢一次租约 —— 正在跑的时候换不了。

## 还考虑过什么，为什么没选

- **只改内存里的配置**：那是把事实当成设置。三个后果：审计查不到"谁什么时候换的"；重放对不上（同一串事件必须折出同一个模型配置）；断线重连的那一端不知道现在是谁在生成。参考的做法只改内存，是因为它的会话状态本来就在内存里 —— 我们的会话是折出来的。
- **当轮立刻生效**：那一轮的模型调用可能已经在飞了，改了只会让这一轮的账说不清。
- **把换模型做成"新开一条会话"**：那会丢掉上下文和当前的工作位置，代价远大于收益。

## 代价与换来的

- 换模型要走完整的写入路径（抢租约、落事件），比改一个字段慢。
- 换来的是：会话当前用的是哪个模型是**折出来的**，不是另一份要跟着同步的状态；换模型这件事在历史里看得见。
