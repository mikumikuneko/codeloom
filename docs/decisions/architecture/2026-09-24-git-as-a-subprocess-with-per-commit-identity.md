# 决策：直接调 git 子进程，提交身份每次显式传

## 是什么问题

整套并发模型压在 git 的 worktree 上，那 git 本身要怎么用？用库（JGit）还是直接调那条 `git` 命令？提交是谁写的，怎么保证不出错？

## 定了什么

**直接调 `git` 可执行文件**（`GitClient`），不用 JGit。每条命令都带一串硬化的 `-c` 参数：中和 `core.hooksPath`、`core.fsmonitor`、`diff.external`、`credential.helper`，固定 `core.autocrlf=false`、`core.longpaths=true`，环境里设 `GIT_CONFIG_NOSYSTEM=1`、`LC_ALL=C`、`GIT_TERMINAL_PROMPT=0`。worktree 里的内容对 agent 可写，所以这些参数是纵深防御 —— 成本是一行，收益是"worktree 里的文件不会让 git 去执行任意命令"。

**提交身份每次显式传**：`-c user.name=… -c user.email=…`，不设仓库级身份。身份只出现在**会产生提交的那几个入口**（`runAs` / `runAsOrThrow`），读命令一律不带 —— 否则"这次提交是谁写的"就看不出来了。

## 还考虑过什么，为什么没选

- **JGit**：git 的 linked worktree（独立 HEAD、独立索引、`.git` 是个指向主仓库的文件）在 JGit 里支持不完整，而我们的并发模型正压在这个语义上 —— 用它就得自己实现 worktree 语义，等于把架构基石建在流沙上。直接调命令反而"用的就是我们依赖的那个东西"。
- **仓库级 `user.name` / `user.email`**：一棵树会被同一个人的多条会话共用，仓库级身份会让"这次提交是哪条会话、哪个账号产出的"看不出来；而且忘了配要等到第一次提交才炸，报错点离原因很远。每次显式传的话，忘了传**立刻**报错。
- **不带那一串硬化参数**（相信 worktree 的 `.git` 是文件、agent 碰不到主仓库配置）：仍然显式中和一遍 —— 纵深防御，一行参数而已。

## 代价与换来的

- 每个跑应用的机器上都得有 git 可执行文件（路径可配）。
- 输出得自己解析：换行符、中文路径的八进制转义（`core.quotepath=false`）、`nothing to commit` 这类英文串匹配，都归我们管 —— 所以 `LC_ALL=C` 是必须的，它不只是"好看"。
- 身份要手工穿到每个产生提交的入口；穿错了没人拦（这条已经收窄成两个入口，见 `runAs` 那对）。
- 换来的是：worktree 语义和 git 官方实现完全一致，提交的作者信息可靠且可审计。
- 退出码必须分开处理：**1 = 冲突**（正常业务路径，"没有改动"也走它）、**128 = 致命**。混在一起处理，会把"这次没有任何改动"当成失败，或者把真正的致命错误当成需要人裁决的冲突。
