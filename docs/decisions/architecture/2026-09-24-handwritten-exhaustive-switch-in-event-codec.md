# 决策：事件编解码手写穷尽 switch，不用 Jackson 的多态注解

## 是什么问题

事件是一个 sealed 的 record 层级（二十多个类型）。它和"类型名 + JSON"之间的映射怎么写？一行注解就能让 Jackson 自动分派，还是手写？

## 定了什么

`EventCodec` 里**手写两个穷尽 switch**（编码一个、解码一个），两个都不带 `default`。新增一个事件类型，这里**编译不过**。

## 还考虑过什么，为什么没选

- **Jackson 的多态注解**（`@JsonTypeInfo` / `@JsonSubTypes`）：一行注解就能工作，但有两个硬伤。一是注解得加在 domain 的 sealed 接口上 —— 零依赖的领域类会因此依赖序列化框架，以后换格式还要改领域代码。二是更要紧的：**注解是一份手工清单**，新增事件类型忘了登记，编译不报错，只在运行时炸（而且是在反序列化那一刻、在一个和它没关系的地方）。
- **让全局 Jackson 配置来管**：落库格式会被全局配置牵着走（比如有人为了"响应体更瘦"打开 null 省略，历史事件就会被重新编码成另一种字节）—— 同一个事实两种字节，是 append-only 日志最不该出现的事。所以编解码自己配了一份 mapper。
- **给 switch 加 `default` 兜底**：那就把编译期防线拆了；而"读不懂的类型"应当**拒绝整条日志**（见"只建一张事件表"那篇），不是安静跳过。

## 代价与换来的

- 每加一个事件类型要改两处（编码、解码）+ 事件类型枚举。这是有意的摩擦。
- 换来的是：**编译器替我们记着这件事**；落库的字段名就是 record 的组件名，不受任何全局配置影响；类型名一旦发布就不能改（改一个常量名，历史行整体读不出来）。
