# 决策：工具的呈现是声明式的，渲染函数不写进事件

## 是什么问题

工具调用在界面上怎么显示（"读文件 X""跑命令 Y"）？后端算好一句话发过来，还是前端自己拼？

## 定了什么

工具**声明**呈现需要的三样东西：形状（读/写/执行…）、用哪个词、主语对应哪个参数（`ToolSurface`，工具通过 `Tool.surface()` 声明）；前端照着渲染。**呈现用的数据不进事件流** —— 事件里只有工具名和参数这些原始事实。

## 还考虑过什么，为什么没选

- **后端返回渲染好的字符串**：那要把界面文案塞进**不可变的事件流** —— 等于把 UI 烤进历史：改一次文案要动历史，而历史是 append-only 的，改不了。多语言更没法做。
- **让后端跑一段渲染函数**（把呈现逻辑写成代码，调用时执行）：我们的客户端是**另一个进程、另一种语言**，跑不了后端的函数；真要跑就得把结果序列化过去，那又回到了"把 UI 烤进历史"那条路（要么进事件，要么进每次响应的额外文本）。
- **前端硬编码每个工具的文案**：工具是会长出来的，每加一个工具都要改前端两处（列表和渲染）。

## 代价与换来的

- 前端要维护一套"按形状渲染"的组件（读、写、执行各自的排版）。
- 换来的是：历史与界面解耦（改文案不动历史）、新工具只要声明一次、前端拿到的永远是原始事实加一份声明。
