# 决策：平台密钥无默认值、不自动生成

## 是什么问题

有一把平台自己的密钥（用来加密用户存进来的各家 API key）。配置里它没配上的时候怎么办？给个默认值、还是启动时自动生成一把？

## 定了什么

**都没有**。`codeloom.secret-key` 没有默认值，也不会自动生成；没配就是启动失败（或者相关功能明确不可用）。

## 还考虑过什么，为什么没选

- **启动时自动生成一把**：听起来最友好，实际最坏 —— 它**每次重启就换一把**，于是库里已经加密的东西"一夜之间全部解不开"。而那时用户看到的是"我的密钥怎么都没了"，不是"配置错了"。
- **给一个写死的默认值**（比如开发用的固定串）：那等于把加密降级成一个混淆，而且这个值会进版本库。
- **做成界面上可配的一项**：它是"锁住所有人 key 的那把锁"——界面上不该有那一格（谁填、填了谁能看）。

## 代价与换来的

- 新环境上手时要显式配一次（本地用 gitignore 的本地配置、部署用环境变量）。
- 换来的是：**"密钥解不开"这件事不可能悄悄发生**；没有默认值也意味着"忘了配"会在第一次用的时候响，而不是在几周后以数据丢失的方式暴露。
