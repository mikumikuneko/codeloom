# 决策：后端不再回落到"平台开发用的 key"，界面是配 key 的唯一入口

## 是什么问题

本地开发时，每次都要在界面上配一遍自己的 API key，很烦。要不要在后端留一条"没配就用平台那把开发 key"的回落？

## 定了什么

**删掉那条回落**。没有 key 就是没有 key（建不了会话，本地也一样），界面是配 key 的唯一入口。

## 还考虑过什么，为什么没选

- **保留回落**：它让"这份凭据算谁的"变含糊 —— 按账号算的额度、限流、以及"这条会话花了谁的钱"全都跟着含糊。一个开发便利换来的是一整片说不清的账。
- **回落但打日志**（"这次用的是平台 key"）：日志不是答案；问题的性质是"资源归属不明"，不是"没记录"。
- **只在本地 profile 里留着**：那还是两套行为，而"本地跑起来和线上不一样"会在最关键的时候咬人。

## 代价与换来的

- 本地开发每次换环境都要在界面上配一次 key（BYOK 的代价，也是它该有的样子）。
- 换来的是：**凭据的归属永远只有一个答案** —— 谁的账号就是谁的 key；顺带把"平台上替你花钱"这整套不存在的场景（配额、账本）也一起清掉了。
