# 决策：要覆盖一个文件，先在这一轮里读过它

## 是什么问题

模型要写一个已经存在的文件。凭什么允许它覆盖？防的是"没看过就改"（盲改），还是"改了别人刚改过的东西"（覆盖掉别人的编辑）？这两件事要的机制不一样。

## 定了什么

判据是**"这个文件在这一轮对话里被读过没有"**（`ReadLedger` 记账）：`write_file` 能新建、也能覆盖**读过的**文件；`edit_file` 走精确局部替换。**不比修改时间，也不比内容。**

## 还考虑过什么，为什么没选

- **写之前比修改时间**（记下读它那一刻的 mtime，写时对一次）：那是防"读完之后被别人改了"，但它要求写路径上维持一套读状态；而我们这两条写路径本来就不会拿旧全文覆盖别人的改动（`edit_file` 要精确匹配、匹配不上就失败），为"模型少说错一句话"加这一整套不值。
- **比内容**（写完之前再读一遍原文比对）：读路径是**故意做懒的**（大文件只读需要的部分），要比对就得把整个文件物化出来，代价和收益不对等。
- **加一道租约检查**：拦"agent 正在跑的时候人手工改文件"—— 那条是**判断，不是事实**（那一轮工具调用失败重试的代价更小）。
- **只给 `edit_file` 开个"空文件接受空 old_string"的小口子**：那是打补丁；对齐成"读过才许覆盖"更根本，规则也只有一条。

## 代价与换来的

- **已知的洞**：读完文件之后它被别人改了，我们不会发现 —— 账本里只有"路径在不在"，没有版本。这个洞是有意留的，写在 `ReadLedger` 的注释里。
- 覆盖的门槛从"绝对不许"降到"读过就行"，这是主动降的：本意是"别盲改你没看过的东西"，而"读过"正好就是这个意思。
- 换来的是：规则简单可判定（数一遍账本就知道），而且没有第二份要跟着同步的读状态。
