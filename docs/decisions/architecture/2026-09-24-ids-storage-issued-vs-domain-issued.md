# 决策：谁发 ID —— 要排序的存储层发，只要唯一的领域发

## 是什么问题

每条记录都要一个 ID。谁发？数据库、还是领域对象自己？

## 定了什么

**看这个 ID 要不要"全库排序"**：

- 要排序的（事件的全局序号、聊天消息）→ **存储层发**（自增主键）。
- 只要唯一的（用户、项目、会话、工作区）→ **领域层发**（UUID）。

## 还考虑过什么，为什么没选

- **一律用存储层自增**：那些"只要唯一"的 ID 就脱离了数据库没有意义 —— 一个还没落库的聚合根（比如在一次校验里临时构造的 `Session`）就发不出 ID，而"领域对象构造时不需要数据库"是六边形那条线要保住的东西。
- **一律用 UUID**：事件流的全局序号就没有了 —— 那个序号同时是游标、是断线补齐的起点、是回滚的坐标，它必须单调可比较。
- **雪花 ID**（时间有序、性能好）：要协调机器号（多一个要配的全局状态），而且它把**时间戳编码进 ID** —— 而这个 ID 会出现在 git 分支名、URL 和界面上。UUIDv7 本可以兼顾，但 JDK 标准库里没有。

## 代价与换来的

- 两种 ID 并存，读代码时要分清手上这个是哪一种（值对象把这件事写在类型里：`SessionId` 和 `seq` 是两种东西）。
- 换来的是：聚合根不依赖数据库就能构造；而事件序号那条"单调、可比较"的保证由存储层一个自增列给死。
