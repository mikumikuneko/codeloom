# 决策：`temperature` 干脆不发，不留字段也不写死 0

## 是什么问题

模型采样参数怎么处理？界面上给用户两个旋钮（温度、长度）？还是写死一个"适合编码场景"的值？

## 定了什么

**不发**。请求里根本不带 `temperature`（字段从配置里删掉，表里那一列也删了）。单次输出上限（`maxTokens`）则从会话配置挪进了模型能力表 —— 它是**模型的属性**，不是会话的属性。

## 还考虑过什么，为什么没选

- **写死 0**（编码场景文档里推荐的那个值）：它是有依据的，但用户拍板选了"不发" —— 理由是**少一个不该由我们决定的假设**：实际生效的会变成服务端的默认值，而这件事由模型服务自己说了算。
- **保留字段、把界面接上**：给用户两个"通常别动"的旋钮，换来的多半是调坏了再回来问。
- **写死 1**：那是别处的取舍，我们照搬没有理由。

## 代价与换来的

- 行为变化是明确的（写"不发"之前要把这件事说清楚）：采样温度从"我们指定"变成"服务端默认"；顺带也消掉了"推理模型上这个参数生不生效"这个一直说不清的谜。
- 要改表（删列）。
- 换来的是：领域模型里没有"我们其实不打算让人碰、但看起来可调"的字段 —— 那种字段比没有它更糟。
