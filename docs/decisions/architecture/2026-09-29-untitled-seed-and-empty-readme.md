# 决策：项目根是 `untitled/`，里面放一个空的 README

## 是什么问题

新建一个项目时，仓库里第一层应该长什么样？建出来的树要不要预先放一个东西进去？

## 定了什么

项目根是一个叫 **`untitled`** 的目录（跟"文件树里先有项目才有文件"那个习惯一致）；里面放一个**空的 `README.md`**，并且让它进基点提交。

## 还考虑过什么，为什么没选

- **空仓库**（什么都不放）：git **存不了空目录** —— 仓库里没东西，两棵 worktree checkout 出来都看不到那个目录，用户会以为"项目建失败了"。
- **放 `.gitkeep`**：那是给 git 看的占位符，用户看到的是一个莫名其妙的文件；放一个空 `README.md` 至少是"一个项目该有的东西"。
- **放一份模板内容**（README 里写点介绍）：那是替用户决定他项目里该有什么。

## 代价与换来的

- 每个新项目里都有一个空的 README（用户想删就删，删了也不影响什么）。
- 换来的是：新项目建出来是"看得见的、能开始干活的"；而且基点提交里**有东西**这件事，让两条会话分支从第一刻起就是相关的历史（否则第一次合并会撞上"两段历史不相关"）。
