# 决策：非成员回 404，成员但不是所有者回 403

## 是什么问题

一个人访问一个他没权限的项目/会话时，回什么？"没有权限"（403）还是"不存在"（404）？以及"能看见"是不是就等于"能驱动"？

## 定了什么

**两档**，判据是**"对方本来知不知道它存在"**：

- **不是成员** → **404**（对他而言这东西不存在）。
- **是成员但不是所有者**（比如想驱动对方的会话）→ **403**（他本来就能在会话列表里看见它，说谎没意义）。

配套一条："**看得见 ≠ 能驱动**" —— 观战是允许的（能看别人的会话过程），驱动不行（那会污染审计流：一条会话的产出必须能归到一个人）。

## 还考虑过什么，为什么没选

- **一律 403**：会**承认资源存在** —— 一个项目 ID 可以被逐个试出来（枚举），而"存不存在"本身就是不该泄露的信息。
- **一律 401**：把"没登录"和"没权限"混成一件事，客户端没法给出正确的下一步（去登录，还是去要邀请）。
- **允许能看见的人驱动**：两个人在同一棵树上同时驱动各自会话会造成交错，而且"这段代码是谁的 agent 写的"再也说不清。

## 代价与换来的

- 客户端要区分两种失败（"这项目不存在"和"你在里面但别动这条"），文案也要两套。
- 换来的是：不泄露存在性、失败信息与实际权限一致、审计能落到实处。
