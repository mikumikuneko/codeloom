# 决策：清掉旧工具结果要落成事件，不能就地改写

## 是什么问题

上下文快满时，有一招是"把很早的那些工具输出从上下文里去掉"（它们通常又长又只用一次）。做法有两种：把历史里那些消息**就地改写**掉，或者**落一条新事件**说"从第 X 条起不再看了"。

## 定了什么

**落一条事件**（`ToolResultsCleared`），投影照常从事件流折 —— 清理是历史里发生的一件事，不是对历史的编辑。**而且只清读类结果**（读文件、搜、跑命令），`edit_file`/`write_file` 的结果不清。

## 还考虑过什么，为什么没选

- **就地改写那些消息**：那是"投影必须是事件流的纯函数"的直接反面 —— 同一段历史在不同时刻折出来的东西会不一样。多实例下更糟：两个实例折出来的上下文不同，而它们的 prompt 前缀也就不同（缓存全废，行为还可能不一致）。
- **一律清掉最老的结果**（不分工具）：改过什么是下一步判断的依据 —— 清掉它，模型就不记得自己动过哪些文件了。**读来的可以再读，改过的没法再"读回来"**（它已经变了）。
- **清的时候用一句"已省略"占位**：要说清"它还在、只是不看了"，否则模型会以为那次调用没发生。

## 代价与换来的

- 事件流里多一类"元事件"（它描述的是投影怎么被裁剪，不是业务事实）。
- 换来的是：投影仍然是纯函数（同一串事件，任何时候折出来都一样）；多实例之间上下文一致、缓存不白费；而"哪些结果可以清"这条判断只写在一处。
