# 决策：数据库用 MySQL，不用 PostgreSQL

## 是什么问题

关系型数据库选哪家？PostgreSQL 在技术圈的口碑更好，JSONB 这类类型也更"现代"。

## 定了什么

MySQL。

## 还考虑过什么，为什么没选

- **PostgreSQL**：它的强项（JSONB 的索引与查询、GIN 索引、更严格的类型系统）在**这个项目里用不上** —— 事件的 payload 只在应用层反序列化，从来不在数据库里查询或过滤它，所以"能对 JSON 建索引"这件事没有落点。
- **同时支持两家**：那会把 SQL 方言的差异散布到每一处 mapper 上，而我们的 mapper 全是手写的。

**另外一条理由是求职导向的，也如实写下来**：MySQL 是国内后端岗位的通用语言，这个项目要能被讲、被追问、被对上经验。它不是技术判据，但它确实是当时压秤的那一半 —— 决策记录里不该把这种理由藏起来。

## 代价与换来的

- 少了一些 Postgres 才有的表达力（比如更强的 JSON 支持和 `RETURNING` 的写法）。
- 换来的是：SQL 方言的坑少（这个项目手写 SQL 的地方很多）、环境好搭、以及"高频追加写 + `(session_id, seq)` 联合索引"这类真实场景能和面试官聊下去。
