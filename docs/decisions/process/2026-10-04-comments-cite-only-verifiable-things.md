# 决策：注释只引"读者能自己查证"的东西

## 是什么问题

注释里经常要引依据（"某家是这么做的"、"报错原文是这句"）。引到什么程度算合适？把对方的文件路径、内部标识符写进去，看着更精确。

## 定了什么

**判据：读者能不能自己查证。**

- **留**：项目名、错误原文、README 里的原话、公开的环境变量名、协议字段名。
- **去掉**：外部的文件路径与内部标识符（读者没有那个仓库，那就是个死链接）、本机的绝对路径（"我机器上装了在哪"）。
- 引外部的东西要**说清出处**（哪个项目、原话是什么），不能只留一句结论 —— 否则那是一个无法复核的断言。

## 还考虑过什么，为什么没选

- **留着更精确的引用**：精确是给"能打开那个文件的人"的；对这个仓库的读者来说，那些路径既点不开、也搜不到，只会让人以为"这里有个我该看的东西"。顺带还有一种副作用：注释的口气会变成"我读过别人的源码"，而不是"我们为什么这么定"。
- **全部去掉、只留结论**：那就把依据一起丢了，读者无法复核，也会在有人质疑时说不清。
- **放在注释里、但压成一行**（比如只留"依据另有出处"）：等于没写。

## 代价与换来的

- 有些"更精确的细节"被删掉了（想查的人得自己去查）。
- 换来的是：注释里的每一句外部依据**都能被读者当场复核**；同时注释讲的是"我们为什么这么定"，而不是一份读书笔记。
