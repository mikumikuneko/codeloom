# 决策：术语钉子 —— "服务端"是我们这一侧，"服务商"是模型官方

## 是什么问题

同一个词在同一个仓库里被用来指两件事：**"服务端"** 有时指我们这套 Spring 应用（"服务端渲染"、"服务端校验"），有时指模型官方（"服务端返回的 model 字段"）。读的人要靠上下文猜。

## 定了什么

**"服务端" = 我们这一侧**（这个应用）；**"服务商" = 模型官方**（那个 API 的提供方）。全仓按这个词改一遍 —— 代码注释、给模型看的文字、界面文案；测试里的显示名（`@DisplayName`）和字符串字面量不动（那是测试自己的措辞，改了没意义还容易漏）。

## 还考虑过什么，为什么没选

- **不改，靠上下文**：这个词已经在多处出现，而且两处指的正好是"发请求的"和"收请求的"—— 猜错方向不是读不懂，是**理解反了**。
- **换成更长的写法**（"本服务"/"上游模型服务"）：意思不会错，但把一句本来很短的注释撑长，而"服务端/服务商"两个词已经够区分。
- **只在关键处改**：半改比不改更糟 —— 读者会以为剩下的那些是另一种意思。

## 代价与换来的

- 一次全仓替换（涉及面很广，但纯文字）；替换时要把"测试里的措辞"和"界面文案"分开处理。
- 换来的是：这个词以后只有一种意思，读者不用再猜方向。
