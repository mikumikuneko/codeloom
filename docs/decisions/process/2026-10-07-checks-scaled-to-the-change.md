# 决策：检查按改动的面分档，不一律跑全仓

## 是什么问题

改完之后要跑什么？一律全量最保险，但那会变成"改一行注释也跑两分钟"—— 于是人开始不跑。

## 定了什么

**按改动面分三档**：

- 只改注释/文档 → 编译那个模块；
- 改了行为 → 跑那个模块的测试；
- 改了契约（sealed 层级、接口、事件类型） → **全仓**（而且要 `clean`，见"检查要跑在真面上"那篇）。

## 还考虑过什么，为什么没选

- **一律全仓**：看着最稳，实际是把"什么时候该快"和"什么时候必须慢"抹平了。判据不是"保险"，而是**这次改动能影响到哪里** —— 说不清影响面的改动，恰恰要跑全仓。
- **按行数/文件数决定**：改了 sealed 接口的一行，影响面是整个编译单元；改了 UI 的一百行，影响面可能只有那一页。
- **跳过验证**（"这次肯定没事"）：那是把判据换成了感觉。

## 代价与换来的

- 每次要自己判断"这次改的是哪一档" —— 判断错了的代价是漏掉一次回归。
- 换来的是：日常改动快、契约改动认真；而"跑过了"这句话始终带着范围（哪一档、哪一面）。
