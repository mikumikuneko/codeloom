# 决策：一个 `tool_call_id` 只留一条工具消息

## 是什么问题

审批通过之后，那次调用会有两次"回答"：先是我们记下的"用户批准了"，然后是补跑出来的真实结果。两条都留在消息列表里，发出去就报错：

```
role 'tool' must be a response to a preceding tool_calls
```

## 定了什么

**同一个 `tool_call_id` 只许留一条工具消息**，后来的**原地替换**前一条，不追加。

## 还考虑过什么，为什么没选

- **追加两条，让模型自己理解**：协议不允许（模型那边会直接 400），而且两条互相矛盾的回答对模型也没有意义。
- **第一条不落进消息列表**（只在事件流里当记录）：那"用户批准了什么"就从模型的上下文里消失了 —— 模型会以为这个调用是凭空跑的。
- **在发送前临时去重**：那是把不变式放在离问题很远的地方；一旦有第二条路径产生回答，它照样漏。

## 代价与换来的

- 消息列表的构造要按 id 索引（不能只往尾巴上追加）—— 摞掉了"追加就行"这个简单假设。
- 换来的是：审批那条路（"批准 → 补跑"）在协议上成立；而且这条不变式写在唯一一处（`answerCall`），不会有两份实现。
