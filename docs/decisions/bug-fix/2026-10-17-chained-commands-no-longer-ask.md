# 决策：串联命令按段判，不再整行算「看不懂」

## 是什么问题

模型写命令爱串起来：`javac A.java && java A`、`rm -f X.class && ls`。
`CommandLine` 把 `&`、`|`、`;` 一律当成"解释起来会变样"，整行判成看不懂 ——
免审批名单于是完全失效。实测一轮 hello world，四条串联命令全部要人点批准，
界面上给的理由还是"平台看不懂这行命令要干嘛"。

## 定了什么

`CommandLine.simpleCommands`：按**引号外**的 `&&`、`||`、`;` 把一行切成几条简单命令，
每条各自过 `simpleWords` 与审批判据（程序在不在名单里、路径在不在树内）。
任何一段不合格，整行照样要问。

单个 `&`（后台执行）和单个 `|`（管道）**不切**、仍然算看不懂：管道让数据换了流向，
后台执行让命令跑在谁都不知道的地方 —— 那两件事不是"依次跑几条"。

## 还考虑过什么，为什么没选

**把 `&` / `|` / `;` 直接放进白名单。** 否决：管道和重定向正是"看不准它会动什么"的
来源，放行等于把整道判据关掉。

**写一个真解析器。** 否决：同 `CommandLine` 类注释里的理由 —— 简化解析器的失败方式是
"我切错了但我说没问题"，比"多说一句看不懂"坏得多。这里只做一件事：按引号外的
`&& || ;` 切段，切段本身没有歧义。

## 代价与换来的

- 串联里的**每一段都独立受查**，所以放宽的只是写法，不是内容。
- 引号里的 `&&` 不切（`echo "a && b"` 仍然是一条）。
- 空段（`a &&`、`&& a`）与引号没配平仍然看不懂。
- 分支语义（`&&` 前一条成功才跑、`||` 前一条失败才跑）不再被"看不懂"挡住，
  但也不会被模拟 —— 判据只看"每一段各自合不合规"。
