# 决策：子进程的环境是重建出来的，不是继承下去的

## 是什么问题

租约、审批、路径守卫这些都在管"agent 能做什么"，没有一处管"它继承了什么"。而 `run_command` 起的是一个真子进程，进程的环境默认从应用继承 —— 那里面有 `CODELOOM_SECRET_KEY`，也就是解开库里用户 API Key 的那把主密钥，还有中间件口令。批准与否都不影响这件事：一条 `echo` 就把它读走了。

回头看"子进程能碰到这台机器上它能碰到的一切"那句话时发现的：那句话讲的是文件与网络，环境变量根本没被提过，因为当时没人往那边看。

## 定了什么

`ProcessRunner` 是**唯一的**子进程卡口（git 和模型命令都从这里过），子进程的环境由它**重建**：先把本进程的环境清一遍，再合并调用方显式给的 `extraEnvironment`。

清洗规则两条，都长在 `ProcessRunner` 上：

- **凭据形状的名字**（`KEY` / `PASSWORD` / `SECRET` / `TOKEN`，不区分大小写）一个都不递下去；
- **整片 `CODELOOM_` 命名空间**丢掉（比前缀前先 `toUpperCase`，因为 Windows 的环境名不区分大小写）。它里面除了口令，还有 `CODELOOM_COMMAND_WHITELIST` 这种**不该让模型看见**的调参。

顺序是契约：**清洗在前，显式合并在后**。所以"这个程序确实需要某个变量"走 `extraEnvironment` 那条路，而默认那条路是干净的。

## 还考虑过什么，为什么没选

- **维护一张敏感变量名单**：会漏，而且每加一个新变量都得记得回来补；形状匹配自动盖住。名单 + 默认关闭那条路更糟 —— 默认关掉的安全措施等于没有，只在 CI 里开着防不住本机上的一次 `echo`。
- **白名单式最小化**（只留 `PATH`、`HOME`、locale、代理变量）：最容易把子进程跑坏 —— 某个工具悄悄依赖一个变量，表现是"这个程序在我机器上不工作"，而且很难指到原因。收益不值这个风险。
- **只在 `LocalCommandExecutor` 那一处清**：git 也走同一个 `ProcessRunner`，主密钥同样会进 git 的子进程；而且"两个卡口各自记得清"迟早分叉。
- **加一个总开关**：能关掉的安全默认就是会被关掉的默认。
- **只给一份最小环境，让每个调用方自己加回来**：那等于把每个调用方都变成"必须记得加 `PATH`"的人，而漏掉的那个会以最难查的方式坏掉。

## 代价与换来的

- **误伤**：带这几个字样的普通变量也进不去（`TOKENIZERS_PARALLELISM` 这类）。后果是那个工具在子进程里读不到它 —— 比漏掉一把真密钥轻。
- **要显式传凭据的场景变麻烦了**：某个项目真要 `NPM_TOKEN` 才能装依赖时，得走 `extraEnvironment`，或者承认这条路不通。默认干净换来的就是这一层不便利。
- 换来的是：**不需要审批、也不需要沙箱**，模型就再也读不到那把主密钥。这是"没有硬隔离"这个前提下能做的最小的一件事。
- 它**不改变**"审批的边界是项目"和"工作区放在这台机器上"两篇的结论：命令仍然能碰到这台机器上的文件与网络，沙箱仍然是另一件事。这一条只收窄了"继承了什么"。

## 什么情况下该重新考虑

沙箱真的落地之后这条仍然留着 —— 它是纵深防御的一部分，不冲突。真有人抱怨某个凭据传不进子进程时，先看它是不是该走 `extraEnvironment`。
