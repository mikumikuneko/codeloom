# 决策：用量行等这一轮真正跑完才出现

## 是什么问题

一次工具调用挂着等人批时，后端会先把挂起那一刻的结算落下来（状态 `AWAITING_APPROVAL`、
一条 `TURN_TOKENS_USED`）。批准之后，这一轮**接着跑**，跑完再结算一次。

原来的判据是"这一轮是不是还挂在 `AWAITING_APPROVAL`"：挂起时不画用量行，别的时候画。
这漏掉了批准之后那一段 —— 状态一离开 `AWAITING_APPROVAL` 就变成"可以画"，
于是续跑刚开始，屏幕上就冒出"这一轮用了 4,894 tokens · 用时 4 秒"；等续跑真跑完，
那个数还会再变一次。人看到的是**先出现、又跳一下**，而这一轮明明还没结束。

## 定了什么

用量行只在**这一轮真的结束**时出现（`usageLineVisible`）：

- 终态 `WAITING_USER` / `FAILED`：画；
- 这一轮留下了一条 `turnEnd`（失败 / 打断 / 拒绝）：画；
- 历史轮次（不是最后那一轮）只要不是停在 `AWAITING_APPROVAL`：画 —— 老数据可能没有状态条目，不能把它们全藏掉；
- 其余（`THINKING`、`EXECUTING_TOOL`、`IDLE`、`AWAITING_APPROVAL`、还没有状态）：不画。

还有一处更细的：批准之后，后端会先把状态从 `AWAITING_APPROVAL` 推到 `WAITING_USER`，
**然后才开始续跑**。那一瞬的 `WAITING_USER` 不是"这一轮完了"，而是"挂起那一段收完了"。
所以再看一眼这一轮的**最后一条实质条目**（状态 / 检查点 / 用量都不算实质）：
如果它就是那条刚被批准的审批，说明续跑还没有任何产出，也不能画。

## 还考虑过什么，为什么没选

**只判 `AWAITING_APPROVAL`（原来的写法）。** 它在批准后的续跑期间会漏判 ——
这正是这次修的洞；状态离开审批态不等于这一轮结束。

**只判"还在不在跑"（`turnIsActive`）。** `AWAITING_APPROVAL` 的 `active` 是 `false`
（等人批时不能打断），照它判会在挂起那一刻就画出来 —— 和要修的洞正好相反。

**只在不是最后那一轮时画。** 那会把刚刚跑完的那一轮的结算藏到下一句话开始之后，
而人正想在那时看一眼花了多少。

**用一个定时器等一会儿再画。** 续跑什么时候开始是后端的事，定时器只能猜；
猜短了照样闪，猜长了每一轮都晚半秒。判"最后一条实质条目"不需要猜。

## 代价与换来的

- 规则多了一条：用量行看不看得见，取决于这一轮的状态**和**最后一条实质条目。
  它被抽成纯函数并有单测（挂起 / 续跑 / 终态 / 拒绝 / 历史数据）。
- 换来的是：用量行只在真正跑完时出现一次，不再在批准之后先闪一下、再跳一次。

## 什么情况下该重新考虑

如果后端改成"挂起时**不**结算、整轮只结算一次"，这条特判就可以删掉 ——
那时只有一个用量事件，判终态就够了。
