# 决策：界面不再自己数轮次，改用后端那个号

## 是什么问题

"这一轮改了哪些文件"会挂到**别人那一轮**头上。看起来完全像真的：数字对、文件对，只有轮次错。

根因是界面上有**两套轮次编号在并存**：

- 屏幕上分块用的是"第几块"（见 `groupIntoTurns`）；
- 那条改动记录的位置是界面**自己数用户消息**数出来的。

而"轮次号"这件事早就定过了（见"轮次号按'这一轮跑完了吗'推进"那篇）：号只在**这一轮跑完**时推。那篇里还写着，界面当年之所以自己数，是**为了绕开**"批准会让后端号多推一格"—— 而那个毛病后来在字段那一侧修好了，**这个绕道没人撤**。于是它留了下来，和分块那套又对不上：开头只要有一条不是用户消息（比如别人先捎来一句话），整条流的改动就整体错一格。

## 定了什么

**那个号写进事件里，界面直接读。**

- `WorkspaceChanges` 多一个 `turnIndex`，和同一次收尾那条 checkpoint 记的是**同一个数**（两者算的是同一个推进后的会话，见 `SessionWriter.settle`）。
- 会话流按**块号**挂号（屏幕上第几块就是第几块，这是排版概念，不需要号）；回滚面板按**后端号**挂号（它列的那些位置本来就是后端号）。两条路各自和自己那套对齐，谁也不去猜另一套。
- 字段**可以为空**（加它之前落的事件没有）。缺字段读成 `null`，**不默认成 0** —— 0 是一个合法的轮次号，缺字段读成 0 会指向第一轮，那比"不知道"坏得多。

## 还考虑过什么，为什么没选

- **在界面上把两套数法对齐**：做过一版（让分块和挂号同源）。它能消掉"两套"里的那一对，但界线仍旧是**界面自己数**—— 将来界面再有人按位置推轮次，同样的错会再来一次。根子上是"一件事两个定义"，那就该收口到一个。
- **让后端在**每一条**可能被挂到轮上的事件里都带上号**：改动记录这一条是唯一需要的（其余要么不显示，要么本来就不挂轮次）。多带的字段没人读，而没人读的字段比没有它更糟。

## 代价与换来的

- 代价：老事件（加字段之前落的）在**回滚面板**里那两列是空的 —— 那一段改动显示不出来。**这是刻意的**：拿位置去猜一个号塞进去，猜错就是"那句话配着别人的改动"，而那看起来像真的。会话流那一侧不受影响（它按块渲染，位置本来就是对的）。
- 代价：那条事件多了一个字段。
- 换来的是：界面上"轮次"只剩**一个定义**，而且就是那个定过的号。

## 什么情况下该重新考虑

如果哪天要做的不是"标注这一轮的改动"而是"整轮的回放/对比"，那时该谈的是把一轮的**边界**也写进事件，而不是继续在界面上按位置推。
