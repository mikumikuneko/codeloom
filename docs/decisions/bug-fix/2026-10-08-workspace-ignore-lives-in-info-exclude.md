# 决策：忽略规则写在 `.git/info/exclude`，不往用户项目里塞 `.gitignore`

## 是什么问题

工作区里有些文件不该进版本库（落盘的溢出输出之类）。忽略规则写在哪儿？平台曾经的做法是：初始化仓库时替你写一份 `.gitignore`。

## 定了什么

只写 `.git/info/exclude`（git 官方的**本地**忽略文件，不进版本库），平台不再往用户的项目里写 `.gitignore`。

## 还考虑过什么，为什么没选

- **写 `.gitignore`**：它是**项目自己的文件** —— 会进版本库、会出现在每一轮的 diff 里，等于往别人的项目里塞了一个不属于他的文件。实测也确认了：那份 `.gitignore` 真的进了基点提交。
- **两条都写**：规则有了两个家，改一处忘一处；而且 `.gitignore` 那条路的问题依旧。
- **不忽略**（让那些文件出现在 diff 里）：用户会看到自己没写过的改动，而"这一轮改了什么"是我们最要干净的输出。

## 代价与换来的

- 用户自己 `git status` 时看不到这些忽略规则（它们在本地的 `exclude` 里）—— 但它们本来也不该是他关心的事。
- 改动连带了几处（布局的过滤逻辑、相应的接口测试断言）。
- 换来的是：**用户的项目保持干净** —— 我们只在他的工作区里干活，不往他的版本库里放文件。
